# 关键技术

[返回项目首页](../README.md) · [研究路线](research-route.md)

本文介绍项目已经使用或检验的技术思路。不同组件属于不同实验分支，具体组合需要独立评估。

## 实例与语义两条建模路线

实例路线采用Mask R-CNN，学习候选区域、分类与实例掩膜；语义路线使用图像裁块学习前景。项目比较它们的误差和成本，再研究满足明确条件的跨模型融合。

融合时保留实例身份、原坐标及确定的冲突处理顺序。两种模型的概率具有不同语义，简单平均不被解释成已经校准的后验概率。

## 原生坐标与实例条件细化

检测尺度、ROI尺度和图像原生尺度之间的映射会影响细结构。项目保存必要的坐标关系与概率表示，在实例附近进行局部细化，再还原为完整输出。

图像、原实例概率与空间上下文共同提供修正信息。评价同时关注匹配改善、边界侵蚀和连接丢失。局部裁块的变化、拼接行为与最终实例竞争分别检查，避免把中间表示的改善直接当作完整输出改善。

## 多标注监督

同一图像可能有不同的人工标注集合。项目保留各套标注，不直接将它们拼接为一份无冲突真值。

已检验的一条路线是：当另一套标注在对应候选内给出正监督，而当前目标给出负监督时，屏蔽符合规则的冲突负像素，同时保留原有正例。这个设计只处理监督冲突，并不判断哪套标注一定正确，也不保证最终误检更少。

## 候选质量与交叉拟合

候选研究使用掩膜、类别、框几何、ROI表征和候选间关系等信息。已检验质量评分、边际新增覆盖、不同目标状态与相对排序等配方。

训练评分器时需要追踪特征的完整来源：生成候选的教师是否见过对应验证图像？归一化是否只使用训练侧？是否在预测冻结后才进行留出评价？项目通过时间分组和交叉拟合检查这些边界。

候选覆盖、排序质量与最终分割指标是不同量。某个候选在GT已知时有用，不代表模型能可靠识别它，更不代表多个候选可以无冲突地同时加入。

## 评测与输出约束

- 对照冻结的评测实现，核对实例匹配和全局聚合行为。
- 同一物理图像预测一次，再对应不同标注记录进行评价。
- 使用COCO RLE表示实例掩膜，检查坐标、面积、唯一身份与互斥要求。
- 通过配对时间组重采样描述特定比较的不确定性，同时保留训练随机性和历史选择暴露的限制。
- 定量指标与形态检查并列，记录改善与损伤。

## 实验工程

| 能力 | 作用 |
|---|---|
| 冻结协议与来源记录 | 让配置、输入、权重和结论能够对应 |
| 完整断点恢复 | 保存模型、优化器、调度与随机状态，检查恢复路径 |
| 原生概率与候选缓存 | 在输入条件允许时复用已有计算 |
| 数值等价验证 | 对插值、排序、精度与I/O优化检查输出变化 |
| 分阶段计时 | 区分模型运算、后处理、写盘、传输与监督开销 |
| 资源守卫与受控退出 | 让有界实验能够安全停止并保留已有产物 |
| 归档核验 | 用清单与内容哈希关联文件、版本和实验身份 |

这些工程措施帮助追溯和复现实验。程序正常退出、文件核验通过或推理加速，都不能单独证明模型质量提高。
